# 해외출원 file wrapper 사건 폴더 정리

도구: `tools/kipris-filewrapper` (자세한 내용은 그 폴더의 README.md "사건 폴더 정리" 참고)

## 폴더 구조

```
<사건루트>/                            (config.json 의 casesRoot, 없으면 사용자에게 경로를 물어볼 것)
  <관리번호>_<국가>_<출원번호>/         예: ABCD240001EPA_EP_22123456  (관리번호는 생략 가능)
    이력.txt                           KIPRIS 심사목록 표 (없으면 캡처 이미지로 만든다)
    이력1.png, 이력2.png ...           KIPRIS 심사목록 상세화면 캡처 (선택)
    *.pdf / *.zip                      사용자가 KIPRIS에서 받은 주요 서류
```

## 절차

1. 사건루트의 하위 폴더를 확인한다. `_`나 `.`로 시작하는 폴더는 건너뛴다.
2. 각 사건 폴더에서 **이력.txt가 없고 캡처 이미지(png/jpg)가 있으면**, 이미지를 파일명 순으로 모두 읽고 이력.txt를 만든다.
   - 첫 줄들은 상단 서지 정보: `출원번호<TAB>값`, `출원일자<TAB>값`, `발명의 명칭<TAB>값`, `출원인<TAB>값`, `등록번호<TAB>값` (화면에 있는 것만)
   - 그 다음 표의 행을 위에서부터 한 줄씩: `서류명<TAB>YYYY.MM.DD<TAB>문서그룹`
   - 서류명은 화면에 보이는 그대로 (괄호, 슬래시 포함) 옮긴다. 번역하거나 줄이지 않는다.
   - 스크롤해서 찍은 캡처끼리 겹치는 행은 한 번만 적는다. 단, 같은 날짜에 같은 서류명이 실제로 여러 번 있는 경우(예: Annex, Electronic Receipt)는 화면에 있는 개수만큼 적는다.
   - 글자가 흐려 확실하지 않은 부분은 추측하지 말고 `[?]`를 붙이고 사용자에게 알린다.
   - 마지막 캡처가 표의 끝이 아닌 것처럼 보이면(스크롤바가 남아 있는 등) 사용자에게 알린다.
3. 이력.txt가 이미 있으면 그대로 쓴다 (사용자가 표를 복사해 붙여넣은 것일 수 있음). 덮어쓰지 않는다.
4. 실행:
   ```bash
   cd tools/kipris-filewrapper
   npm run cases -- "<사건루트>"
   ```
   처음이면 먼저 `npm install`.
5. 출력의 `[확인: ...]` 항목(이력.txt 없음, 이력에 없는 파일)을 사용자에게 요약해서 알려준다.
   이력에 없는 파일은 파일명 날짜/서류명이 KIPRIS 이력과 다르다는 뜻이므로, 이력.txt의 어느 행인지 사용자에게 확인받아 파일명을 `YYYYMMDD_이력의서류명.pdf`로 바꾼 뒤 다시 실행한다.

## 지킬 것

- 사용자가 넣은 원본 파일은 수정·삭제·이동하지 않는다. 결과는 각 사건 폴더의 `정리/`와 사건루트의 `file_wrapper_이력.xlsx`에만 쓴다 (매 실행마다 새로 만들어짐).
- 사건 자료(캡처, PDF, 이력.txt, 엑셀)는 고객사 정보다. 이 저장소는 public이므로 절대 git에 추가하거나 커밋하지 않는다.
